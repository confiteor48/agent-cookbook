# Browser State and Settings Verification

Use the documented browser API and the provider's supported API before lower-level UI techniques. Keep these rules alongside the platform's browser safety and confirmation requirements.

1. Accessibility and DOM representations can expose different roles for the same control. A native accessibility checkbox may appear as a DOM button with `aria-pressed`. When using Playwright locators, derive their roles and names from a fresh DOM snapshot rather than copying a native accessibility role. Inspect the current representation after a selector mismatch instead of inventing variants or repeating the same action.
   A text input associated with a mounted `datalist` can expose the combobox role instead of textbox. Check its current representation after asynchronous suggestions load.
2. Treat immediately changed controls as optimistic state until the provider confirms persistence. Wait for the save acknowledgement and verify the saved value after reloading or through an authoritative API before applying a dependent setting. Rapidly chaining dependent toggles can cancel, race, or conceal an unsaved change. A success message for a previous setting does not verify the next one.
3. Reconcile a failed or uncertain settings write against durable state before retrying. If the setting remains disabled after a completed reload, target that known state; if the save is still pending, continue independent work instead of issuing another toggle that could undo it.
4. After a full-page screenshot timeout, preserve the tab and try the documented normal-viewport capture. A screenshot failure alone does not establish disconnection or loss of page state. Save proof showing the relevant result and its page context; use the documented scrolling or screenshot options rather than rebuilding the browser session unnecessarily.

5. Rich text and code editors can ignore an accessibility value assignment or insert text without replacing their existing document. Verify the actual editor content before saving. If a supported fill operation prepends or appends instead of replacing, focus the exact editor, use its documented Select All and Backspace controls, verify the editor is empty, then enter the replacement and verify both its beginning and end. Save once, wait for acknowledgement, and read the persisted content before publishing; an action returning successfully does not prove the old text was removed.

6. Editing a compiled frontend asset without changing its fingerprint can leave browsers running cached old code after a reload. Version each changed bundle and its loader references, including auxiliary runtime scripts, before verification or publication. Compare the actual served bytes with the candidate and verify a fresh browser load uses the new asset URLs. Preserve user storage and saved dashboards; do not clear them to conceal an invalidation defect. Distinguish newly timestamped console failures from retained older logs, and verify removed network hooks in the executed code rather than treating a blocked request as removal.
   Apply the same completeness check to recovery: resolve every script and stylesheet reference in the restored entry document before starting the service, including auxiliary loaders outside the known custom fingerprints. An API response and a few matching assets do not prove that the restored frontend boots. If a retained rollback point contains a known missing alias, preserve that backup and apply only the separately verified, exact-byte repair during recovery; refuse unrelated missing or mismatched assets. Verify the public frontend renders after recovery, and distinguish this from authenticated playback or other application acceptance.

7. Test a single-page application from both its entry URL and a directly loaded nested route. Auxiliary scripts, styles and manifest references must resolve from the intended deployment root after navigation and a full reload; entry-page success does not prove deep-route startup works. When a local API adapter filters operations, normalize each explicitly supported host or node prefix before applying the filter, preserving the target identity and same-origin boundary. Verify both prefixed and unprefixed requests; do not broaden the operation allowlist to conceal a missed route.

8. When restoring a control hidden by styling, inspect the complete served stylesheet cascade, including imported legacy styles, runtime rules and hidden ancestors. A fixture must include the winning rules, their specificity and the actual markup; a control may be a direct child in one layout and wrapped in another. Verify computed display and visibility and perform the real interaction on the deployed page. A matching asset URL or an isolated fixture that omits the existing cascade does not prove the control is accessible.

9. Distinguish user selections from initialization and fallback updates at their actual callback boundary. A transient flag captured from a DOM event can expire before an asynchronous or logging wrapper calls the setter, incorrectly blocking a deliberate selection. Pass explicit selection metadata through the native callback and supported setter arguments; initialization must omit it. Verify the deployed event-to-setter path with delayed dispatch, both user choices and automatic resets, persistence after reload, and absence of unauthorized server writes.

10. Verify the final API and asset origins after bootstrap, rather than relying on an initial environment assignment. A loader can mutate fields of the same configuration object later, and root, Agent and local entry variants can select different hosted builds despite sharing an Agent version. Prefer documented configuration hooks; when scoped runtime overrides are requested, keep those specific fields stable while leaving unrelated configuration mutable. Exercise each supported entry variant and compare the actual loaded asset fingerprints before promotion.

11. Read-only browser DOM wrappers may omit native SVG properties such as `ownerSVGElement`. Select the SVG root explicitly and use the observed `viewBox`, path attributes, and bounding rectangle to locate a painted segment when the native geometry API is unavailable. Check the computed point with `elementFromPoint` before clicking. Verify the actual segment interaction separately from its legend button; a successful legend click does not prove the chart itself has the correct hit targets.

12. Verify the inspected tab's actual width and height after setting a responsive viewport. A reused capability handle can acknowledge a setting without changing that tab. If the dimensions remain unchanged, acquire a fresh viewport capability from the same browser binding and verify the result; do not reselect the browser merely to recover the capability. Reset temporary overrides when finished. Page zoom can also make the CSS viewport differ from the requested device dimensions. Inspect both the actual CSS width and measured container width; calibrate temporary emulation dimensions when an exact CSS breakpoint is required, without changing the user's saved zoom. Clear any raw CDP device-metrics override as well as the browser viewport override after verification.

13. Do not iterate positional locators over a list that shrinks after each action. Playwright `locator.all()` can return live `nth()` selectors; closing or deleting the first item shifts later positions and can skip a control or target a different item. Use stable IDs for the intended controls, or resolve the first remaining match after each verified action. After a partial failure, inspect what remains and finish only those actions.

14. Treat waiting OAuth redirects as expiring signed requests. Check request expiry and the existing site session before diagnosing a credential failure. Resume authorization from the existing connector after expiry, preserving its identity and scopes. For a custom consent page, exercise the actual provider response through the served browser script and handle its documented redirect fields; a mocked login or successful server-side code exchange does not verify the browser return. Keep signature and expiry validation intact.
   Keep an OAuth request and its return in the browser profile that initiated the connection; the client can bind callback state to that browser even when the provider accepts consent elsewhere. A saved consent does not prove token exchange. After a callback-state error, reconcile consent and refresh-grant usability before repeating authorization. Recover only the exact matching return in the original client session when supported, or restart the normal connection flow; never edit signed parameters, bypass state/PKCE checks, or print callback codes and state into logs or artifacts.

15. After a remote MCP tool or event schema changes, compare live authenticated server discovery with the client's saved definition before updating a subscription. Use the existing app's supported metadata refresh or rescan controls and explicitly select it for the affected message, then verify actual native discovery. A completed refresh action does not prove an existing chat or task loaded the new schema. Preserve the task, principal and callback binding; keep the task paused while definitions disagree. Do not recreate credentials, weaken server filters or redeploy healthy code merely to match stale client metadata.

16. For MCP Events, a successful callback acknowledges receipt, not completed model work or a source-app reply. Test rapid messages and follow-ups as well as a single event, with batching enabled and disabled where supported. Verify every accepted event's actual read/reply outcome and destination. Native batch execution or notification rules can differ from the saved task prompt; inspect supported task configuration and run evidence before changing transport or claiming a fix. Keep unavailable settings and run traces explicitly unknown. For a prompt-only correction, preserve the task, trigger, principal, callback and privacy boundaries, read back the saved prompt, and repeat the failing burst. Never replay acknowledged events, clear uncertain reply reservations or attempt to override platform instructions merely to force a response. See the [MCP Events delivery and testing contract](https://developers.openai.com/plugins/build/mcp-events).

17. Close a diagnostic login through the provider's normal logout path while its exact authenticated session is still available; closing a local HTTP client or crypto helper does not necessarily release a server-side single-admin session. Keep cookies, tokens and crypto state only in memory, and distinguish local process closure from acknowledged logout or later session expiry. If a subsequent availability check reports an existing administrator, stop before another credential exchange; do not force a takeover, log out an unbound session or repeat login attempts to compensate for lost local session state. Preserve the refusal and resume only when the normal session is available or the user explicitly resolves it.

18. Inspect captured image bytes before choosing a file extension or upload MIME type. A browser screenshot API can return JPEG even when it has no format option. Preserve a format-validation refusal, identify the retained image by its signature, and export those same bytes with the matching extension and content type rather than recapturing a completed observation.
